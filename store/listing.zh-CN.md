## 商店页（中文）

### 名称
cctether

### 简短说明（最多 132 个字符）
让 Claude Code 通过你自己的连接使用浏览器，不经过任何第三方中转。

（和插件里 zh_CN 的简介一致，39 个字符。）

### 详细说明（纯文本，原样粘贴）

cctether 让 Claude Code（或其他 MCP 客户端）读取和操作你 Chrome 里的标签页，走的是你自己搭的连接。不经过任何中转，也没有 cctether 的服务器。插件只连你自己设置的那个服务。

这个插件需要配合一个小服务使用，服务跑在运行 Claude Code 的那台电脑上。没配对之前，插件什么也不会做。

能做什么
你的 Claude Code 需要时，cctether 可以：
- 列出、打开、关闭标签页，跳转网址
- 把页面读成文字，查找页面上的元素
- 截图
- 点击、输入、按键、滚动、悬停、选择下拉选项
- 查看控制台消息和网络请求
- 在页面里运行 JavaScript（和开发者工具的控制台一样）
- 列出已安装的扩展、重新加载其中一个（给扩展开发者用）

怎么保证安全
- 只有放在「cctether」标签组里的标签页才能被使用。共享哪些标签页由你决定，随时可以把标签页拖出这个组。
- 弹窗里有暂停按钮，一按就停下所有操作。
- 开始之前，双方要先证明自己拿着同一把 256 位密钥。之后每条消息都用 AES-256-GCM 加密，中间的代理读不了，也改不了。
- 连到另一台电脑时必须用 wss://。
- 没有统计、没有遥测、没有广告。
- 代码开源（MIT），没有依赖，不压缩，做过一次安全审查（见仓库里的 SECURITY.md）。

怎么设置
1. 在运行 Claude Code 的电脑上运行：npx cctether@latest setup（需要 Node.js 22 或更新版本）。
2. 复制它打印出来的连接码。
3. 在 Chrome 里打开 cctether 的设置页，把连接码粘贴进去。
4. 打开想让 Claude 用的页面，点 cctether 弹窗里的「共享」，也可以让 Claude 自己开新标签页。

cctether 操作标签页时，Chrome 会显示一条「cctether 已开始调试此浏览器」的提示条。点提示条上的「取消」会让 cctether 暂停。

隐私
开发者收不到任何数据。页面内容、截图等结果只会加密后发给你配对的那个服务。插件只在本机保存连接码、设置和一小段最近操作记录。隐私政策：https://github.com/guchaorui/cctether/blob/main/PRIVACY.md

提醒：网页里可能藏着想骗 AI 的文字。银行、邮箱、管理后台这类敏感账号的标签页，除非你在旁边看着，否则不要放进这个组。

cctether 是独立项目，不是 Anthropic 做的，也与 Anthropic 无关联。

源代码：https://github.com/guchaorui/cctether

## 隐私页答案的中文翻译（后台里填英文，这里只是给主人看）

### 唯一用途
让用户自己的 AI 编程助手（Claude Code 或其他 MCP 客户端），通过用户自己运行的服务，读取和操作用户共享的浏览器标签页。

### 各项权限的理由

- debugger：所有页面操作都走 Chrome 的调试器接口，并且只用在「cctether」标签组里的标签页上：真实的鼠标键盘输入、截图、控制台、网络请求、弹框、读取页面。插件没有网站访问权限，也没有内容脚本，所以只有这个接口能做到。操作期间 Chrome 会显示「已开始调试此浏览器」提示条。
- tabs：读取标签页的标题和地址，用来判断哪些标签页在 cctether 组里、给当前标签页显示「共享」按钮，以及在助手要求时打开、关闭、跳转标签页。组外的标签页不会被工具读取或操作。
- tabGroups：创建「cctether」标签组，并且每次调用都检查标签页是不是在组里。助手只能用这个组里的标签页。
- storage：保存连接码（服务地址和密钥）、用户设置（语言、是否暂停）、连接状态和弹窗里显示的最近操作。数据只留在用户自己的电脑上。
- alarms：定时检查连接并自动重连，因为 Chrome 会把闲着的 MV3 后台脚本停掉。
- management：只有 list_extensions 和 reload_extension 两个工具用，让助手列出已安装的扩展、重新加载其中一个，方便用户开发扩展。别的地方不用。

### 网站访问权限
没有。插件不申请任何网站访问权限，也没有内容脚本。

### 远程代码
回答要点：插件包里包含它自己的全部代码，不会下载代码，也不会在插件内部运行从网络收到的代码（没有 eval、没有 new Function、没有远程托管的脚本）。只有一个工具 evaluate，会运行用户自己的 AI 助手经由用户自己的服务发来的一段 JavaScript。这段代码是通过调试器在用户共享的网页里运行的（就像在开发者工具控制台里输入），不是在插件里运行。只作用于 cctether 组里的标签页，只在连着用户配对的服务时才行，用户随时可以暂停。开发者不托管任何代码，也不运营任何服务器。

### 数据使用（勾选哪些）
- 网站内容：用户共享的标签页的文字、HTML、截图、控制台消息和网络请求（含请求头和响应内容）。
- 网页浏览记录：被共享标签页的网址和标题，以及最近操作列表里的网站名。
- 用户活动：助手在共享的标签页里做的点击、输入、按键。
- 身份验证信息：连接码和密钥存在本机；密钥算是一种凭据，助手读到的网络请求头或页面内容里也可能带凭据。数据只留在用户电脑上，只发给用户自己的服务。想稳妥就勾上。

不勾：个人身份信息、健康、财务和支付、个人通信、位置。（助手可能在用户共享的页面上看到这类内容，但插件并不按类别去找或收集它们，见下面的说明。）

三项声明（都勾，对这个插件来说都属实）：
1. 除获批的用途外，不向第三方出售或转让用户数据。
2. 不把用户数据用于与插件唯一用途无关的目的。
3. 不把用户数据用于判断信用或放贷。

隐私政策网址：https://github.com/guchaorui/cctether/blob/main/PRIVACY.md

## 给主人的说明

1. 「远程代码」是最可能被审核员追问的一项。原因是 evaluate 工具会运行 AI 发来的 JavaScript。我们的说法是实话实说：插件自己的代码都在包里，这段脚本是在网页里跑的。审核员问起，就照上面的理由回答。
2. debugger（调试器）是敏感权限，审核通常更仔细、更慢。审核员可能问为什么不用内容脚本，答案是插件故意不申请网站访问权限。
3. 商店版的插件 ID 和你自己加载的那个不一样。在后台新建条目、上传 zip 以后马上就能看到这个 ID。把它告诉 Claude：Claude 会把它加进服务端自带的允许列表，发一个新的 npm 版本，然后你再提交审核。这样商店用户装好就能连，不用改 config.json。
4. 上传的是 `cctether-extension-<版本号>-store.zip`（每个 GitHub Release 里都附着，也可以用 `node scripts/pack-extension.mjs --flat` 打）。它的文件在 zip 最外层，manifest.json 里也去掉了 key，符合商店的要求；自己加载用的那个 zip 保留 key，ID 才固定。
5. 商店页写「for Claude Code」只是说明能配合用，同时声明了与 Anthropic 无关联。图片里不要用 Claude 的标志和配色。
6. 说明里写的「做过一次安全审查」，SECURITY.md 里描述的是一次内部审查，不是外部机构审计。不要改成「已审计」。
7. 数据使用该勾哪些，需要你拿主意。插件会处理共享页面上的任何内容，多勾几项对审核更稳妥。表单填的和实际行为对不上，是常见的被拒原因。
8. 审核员没有你的服务，装上插件只能看到「还没设置」的引导页。如果后台有「测试说明」栏，建议写上：插件需要用户自己运行服务（npx cctether@latest setup），所以只能看到设置界面。
9. 商店截图里不要出现真实账号、真实服务器地址和真实连接码。
